01

What the SDK can do

Two focused API operations for Python applications.

The aidr package gives Python applications access to two OpenSecura API services: known-vulnerability checks for supplied dependency versions, and advisory risk assessments for AI agent activity. Applications can call either service from scripts, CI jobs, or an existing backend.

The local 0.1.0 implementation adds a small public interface over the existing Intelligence client. It preserves the underlying transport, tenant binding, response validation, and service billing receipts. It does not start the desktop app or a local server.

Dependencies

Check the versions you use

Submit exact npm or PyPI package identities. Read vulnerability findings, fixed versions, source references, and per-package availability.

Guardrails

Assess an agent action

Submit an event with task context and optional company policy. Read its score, risk level, category, and confidence.

Both public clients use the same async implementation. The synchronous client runs it on a persistent AnyIO event-loop thread. Package checks and guardrail assessments share a transport within each SDK client.

OperationRequest routeDefault time limit
Dependency scanPOST /v1/services/packages/check25 seconds in the reused package client.

Input ownership

The SDK sends the package identities and guardrail evidence that the caller supplies. It does not discover dependency files, collect agent sessions, or redact guardrail content automatically.

03

Install and connect

Use the local build with a key and its assigned tenant.

Use Python 3.11 or later and an OpenSecura API key with an assigned tenant UUID. The default origin is https://api.opensecura.ai. The SDK constructor validates configuration locally. It does not enroll a device, claim a new tenant, or verify that the key is accepted by the remote service.

Install from the repository root
python -m pip install ./packages/aidr

This is the local 0.1.0 implementation. Publication to PyPI was not performed in this task. The earlier PyPI placeholder does not provide these SDK methods.

Python
import os
from uuid import uuid4
from aidr import AIDR

packages = [
    {"ecosystem": "pypi", "name": "example-library", "version": "1.0"},
    {"ecosystem": "npm", "name": "@example/library", "version": "2.0.0"},
]

# Save this ID and the exact input before submitting if recovery is needed.
request_id = str(uuid4())

with AIDR(
    api_key=os.environ["OPENSECURA_API_KEY"],
    tenant_id=os.environ["OPENSECURA_TENANT_ID"],
) as client:
    scan = client.scan_dependencies(packages, request_id=request_id)
    for result in scan["results"]:
        print(result["query"], result["status"], result["findings"])

The environment variables above are read by the application code. The SDK does not load them automatically. An assigned key can identify its tenant through GET /v1/capabilities, but this discovery is not a public SDK method yet.

Async Python
from aidr import AsyncAIDR

async def scan_packages(api_key, tenant_id, packages, request_id):
    async with AsyncAIDR(api_key=api_key, tenant_id=tenant_id) as client:
        return await client.scan_dependencies(
            packages,
            request_id=request_id,
        )

Reuse a client for repeated requests, then close it. Closing twice is safe. A call after close raises RuntimeError. The async implementation uses asyncio; it is not a promise of compatibility with every async backend.

04

Scan dependencies

Exact versions, known vulnerabilities, and per-package availability.

Provide a list of objects with ecosystem, name, and version. The request is validated before network I/O. npm scoped package names are supported. PyPI package names are normalized, for example Example_Library becomes example-library.

Input or resultBehavior
Accepted ecosystemsnpm and pypi, case-insensitive on input.
Version identityExact supported SemVer for npm and canonical supported PEP 440 forms for PyPI.
Rejected inputEmpty batches, more than 25 packages, version ranges such as ^1.0.0, tags such as latest, filesystem paths, and unsupported ecosystems.
FindingsPrimary vulnerability ID, aliases, source IDs, summary, qualitative severity, fixed versions, severity vectors, and a source URL.
Result orderOne result per input package in the same order. Mismatched identities and missing results are rejected.
FreshnessThe reused validator checks that successful results are current and that expiry is exactly 24 hours after the assessment timestamp.
Return typeA Python dictionary containing results and billing. Successful package timestamps are timezone-aware Python datetime objects.

Scanning a larger project

Resolve the project’s installed or locked versions outside the SDK. Split them into batches of at most 25 and give each batch its own persisted request ID. Automatic file discovery, dependency resolution, transitive expansion, and batching are not implemented.

05

Run guardrail assessments

Structured context and advisory scores, with policy controlled by the caller.

Call assess_guardrail with structured event evidence. The intended state contains a target_event, an optional latest_prompt, a list of prior_events, and a context_limited flag. The wrapper forwards that state to the existing API client; it does not build or truncate the context for you.

Assessment is separate from enforcement

The result has no allow, deny, or approval field. If your product uses score 60 as a manual-review threshold, that is your application’s policy. The SDK does not enforce that threshold or run the proposed action.

06

Handle uncertain results

Separate successful assessments, unavailable evidence, and exceptions.

Successful HTTP delivery does not guarantee a usable assessment. The existing clients validate response shape, package identity, freshness, score consistency, and billing identity. Invalid or unavailable results must remain visible to the calling application.

SituationPublic behavior
Invalid package input or request IDValueError, including Pydantic validation errors, before a service call for the covered cases.
Package request failureScanError with optional status_code, retry_after, error_code, and validated billing.
One package is unavailableA returned result with status='unavailable'; the whole request need not raise.
Guardrail request or validation failureGuardrailError with code, retryable, retry_after, and any validated receipt.
Malformed guardrail scoreAn inconsistent score/category/level is rejected as invalid_response.
Client already closedRuntimeError. Construct a new client if another operation is needed.

Example caller policy
from aidr import GuardrailError

def review_action(client, state, request_id):
    try:
        result = client.assess_guardrail(state, request_id=request_id)
    except GuardrailError as error:
        return {
            "review": "required",
            "reason": error.code,
            "billing": error.billing,
        }

    # Example application policy. This threshold is not an SDK default.
    if result["status"] != "scored" or result["score"] >= 60:
        return {"review": "required", "assessment": result}
    return {"review": "not_required", "assessment": result}

This example reports a review requirement; it does not execute or authorize an action. The reused guardrail client maps HTTP-level service unavailability to provider_unavailable. It does not expose the original HTTP status in GuardrailError, even though ScanError can retain it.

07

Request identity and billing

Keep each operation traceable and retain validated accounting.

Each logical operation requires a caller-supplied canonical UUID string. The client sends it as Idempotency-Key. Generate and save the ID and exact request inputs before submitting when recovery matters. A fresh scan batch or new guardrail assessment needs a new ID.

  1. Before the request: persist the operation ID, input, and relevant options.
  2. After a response: retain the result and matching billing receipt as your application requires.
  3. After an uncertain outcome: reuse the saved ID and identical input if you retry. Do not silently create another logical operation.
Receipt fieldInterpretation
request_idMust match the operation’s submitted UUID.
servicepackage_vulnerabilities or guardrail for these public methods.
stateA validated accounting state such as disabled, reserved, settled, pending, or released.
credits_reservedThe operation’s reservation, as an exact decimal string when applicable.
credits_chargedThe confirmed charge when known. Null is not the same as zero.
rate_versionThe service’s rate identifier, when applicable.
Sample credits are not pricing

The example receipts use a synthetic rate version, test.1, and illustrative credit values. They do not state real pricing, free allowances, or a current account balance. The connected API controls billing.

max_credits is available on guardrail calls as an exact decimal string. The current scan facade does not expose a matching per-call budget option. A timeout is not proof that a billed operation did not run. Both public methods avoid automatic transport retries.

Data and connection behavior

What the client sends and how it connects.

ControlCurrent behavior
AuthenticationBearer API key plus the tenant ID header. The connection checks the credential format and canonicalizes the tenant UUID.
DestinationAn exact HTTPS origin is required. The default is https://api.opensecura.ai. Redirects are not followed.
Trust configurationDefault certificate validation or an explicit PEM bundle through ca_file. Environment proxy settings are disabled by the reused HTTP client.
Sent dependency dataPackage ecosystem, normalized name, exact version, and request identity. The facade reads no project files.
Sent guardrail dataCaller-supplied state and optional company policy. The facade does not automatically redact these fields.
Error detailThe public error path avoids arbitrary service response bodies. Recognized machine error codes can be retained for scan failures.
TelemetryContent-free SDK latency reports are sent only when the API advertises support. Disable with OPENAIDR_SDK_LATENCY=false before client construction.
Local servicesNo desktop runtime, sensor, database, or local HTTP server is required.

Payload retention and model quality are properties of the deployed service. This report verifies client behavior and does not make a new service-retention, detection-accuracy, or latency claim.

10

Code reuse and packaging

Existing clients supply the implementation behind the public interface.

The public implementation lives in packages/aidr. At build time, it verifies the existing Intelligence client wheel against the repository manifest, then bundles that client and the shared helpers under aidr._vendor. Only absolute import paths are rewritten in the bundled sources.

Existing codeHow the public SDK uses it
IntelligenceClient and ConnectionHTTPS transport, tenant binding, bounded responses, request identity, and content-free timing.
ThreatIntelClient.packagesPackage assessment calls, source evidence, per-package validation, freshness checks, and receipt callbacks.
AsyncGuardrailClient.assessGuardrail request construction, timeouts, score validation, and billing validation.
Shared wire contractsPydantic models for package input, responses, and credit receipts.
openaidr_commonExisting helper code and required redaction assets bundled for the client’s internal imports.
Small public adaptersSimple input objects, sync access, context managers, scan error receipts, and preserved scan HTTP status.

The private namespace avoids import collisions with separately installed OpenAIDR clients. The wheel and source archive carry generated code, license files, and provenance. Users do not need a private package index or a separately installed Intelligence SDK.
